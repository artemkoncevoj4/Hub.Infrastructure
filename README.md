# 3. Описание проекта
**Hub Ecosystem** — это веб-платформа-агрегатор, которая объединяет несколько независимых микросервисов под одним доменом, единым интерфейсом и общей системой аутентификации. Пользователь заходит на главную страницу (хаб), видит каталог доступных сервисов и может перейти в любой из них без повторного входа — авторизация сквозная, на уровне всего экосистемы.

Идея в том, чтобы не плодить отдельные сайты с отдельными аккаунтами, а построить модульную экосистему: каждый сервис живёт своей жизнью (своя БД, свой деплой, свой стек), но для пользователя всё выглядит как одно приложение.

## 3.1. **Как это работает**
1. **Пользователь открывает хаб** — единый фронтенд на Vue 3, который ходит в API через общий gateway.
2. **Аутентификация** — отдельный микросервис Hub.Identity.API выдаёт JWT-пару (access + refresh). Refresh-токены хранятся в Redis, access — короткоживущий, летит в заголовке.
3. **Каталог сервисов** — карточки микросервисов с описанием, статусом (Доступно / В разработке) и кнопкой перехода. Если сервис требует авторизации, а пользователь не вошёл — кнопка блокируется и предлагает войти.
4. **Переход в сервис** — Nginx проксирует запрос на нужный контейнер по префиксу пути (/filevault, /chat и т.д.).
5. **Межсервисное общение?** — через Kafka (обёрнутую в MassTransit), чтобы сервисы не были связаны напрямую.

## 3.2. **Ключевые принципы архитектуры:**
 - **Единая точка входа**. Клиент никогда не обращается к сервисам напрямую — только через Nginx. Это упрощает CORS, TLS и маршрутизацию.
 - **Изоляция данных**. У каждого микросервиса своя логическая база в PostgreSQL. Сервисы не читают таблицы друг друга — только через API или события.
 - **Слабая связанность**. Асинхронные сценарии (например, «пользователь зарегистрировался → создать ему корневую папку в FileVault») идут через Kafka, а не через прямые HTTP-вызовы.
 - **Единый UI**. Фронтенд общий для всех сервисов, что даёт консистентный UX и одну кодовую базу.
 - **Контейнеризация**. Всё поднимается одной командой docker compose up — от Nginx до Kafka.

# 4. Стек технологий
| Слой | Технология | Роль в проекте |
| ---- | ---------- | -------------- |
| Frontend | Vue 3 | Единый интерфейс, общающийся с API |
| Gateway | Nginx | Единая точка входа. Принимает запросы от UI и раскидывает их по нужным микросервисам (Reverse Proxy) |
| Backend | C#, ASP.NET Core 10 | Написание самих микросервисов |
| Базы данных | PostgreSQL | Основное хранилище (у каждого сервиса своя логическая БД) |
| Кеш & Сессии | Redis | Хранение Refresh-токенов и кэширование частых запросов |
| Брокер сообщений | Kafka | Ассинхронная шина данных для общения сервисов |
| Интеграция брокера? | MassTransit? | C#-фреймворк, чтобы не писать низкоуровненый код для Kafka |
| Инфраструктура | Docker + Compose | Изоляция и запуск всего проекта |
